Wordflow 0.7.13 is a quick fix for 0.7.12. Wordflow 0.7.11 and 0.7.12 came out over one weekend, so these notes cover everything since 0.7.10.

## Fixed in 0.7.13

- **Page through Quotation results while Run works**: page numbers, **Next** and jumping to a page now work in **Quotation Results so far**; before, only the first page showed. New quotations arriving keep the page you are on, and the table starts at page 1 when the Run finishes.
- **Check for Updates shows your version and what's new**: when Wordflow is up to date, the window now names the version you have (it was blank) and shows its release notes.
- **Help menu finds Wordflow's help**: on a Mac, typing in the Help menu's search field lists Wordflow's help pages instead of unrelated Apple topics, and choosing one opens it. **Help → Wordflow Help** opens the help home on Mac and Windows.

## Highlights since 0.7.10

- **Quotation Runs several times faster, with results as they come**: Run uses several processor cores and shows quotations while it works. **Stop** keeps what was found as a result you can add to the Project, and **Resume** carries on from there, also after a restart.
- **AI annotation that doesn't lose or repeat work**: labels already returned are kept if a run stops, repeated texts are sent once, Run sends only rows without a label by default, and Preview pages you have seen aren't sent again. A slow request no longer fails the whole run.
- **Local AI models work better**: a **Requests at once** setting (2 for Custom providers) stops local servers timing out, and **Thinking** off now really turns thinking off for models such as Qwen, which is much faster.
- **Name your topics**: give Topic Modelling topics their own names; they appear in the topic list, the map and the Data Blocks you add to the Project.
- **Ungrouped passages are shown**: passages that fit no topic appear as **Ungrouped** instead of being left out, and giant topics are split more readily.
- **Map values**: a new Data Editor tool makes a column from a value you type for each value of a column, such as grouping parties into sides.
- **Move table columns**: drag a column header's grip to reorder Concordance, Quotation and Annotation results; downloads and Add to Project keep the order.
- **Suggestions and calmer hints**: a short suggestion appears when a result or run looks off, hints no longer block the page, and tabs are on by default.
- **Ordered categories**: set the order of a category column's values once and every table, filter, group, Trends axis and Topic Map legend follows it (0.7.11).
- **Faster, steadier Topic Modelling on large corpora**: runs finish on a laptop for a 26,000-document corpus, with example texts for each topic (0.7.11).

## What came in 0.7.12

Wordflow 0.7.12 makes Quotation Runs several times faster and shows quotations as they are found; makes AI annotation safer and cheaper, keeping labels if a run stops and sending each text only once; lets you name topics in Topic Modelling; adds Map values to the Data Editor; lets you move result table columns by dragging their headers; shows passages that fit no topic as Ungrouped; and adds suggestions when a result or run looks off.

### Concordance and Quotation

- **Text mode uses no tokeniser**: in Concordance's Text mode the tokeniser now shows None and is not used, also after you've tried Tokens mode.
- **Excel downloads with long documents**: Excel cells hold at most 32,767 characters, so a long document stopped an Excel download of Concordance or Quotation results. The document column is still ticked and marked *recommended*, but you can now untick it to download the other columns; its character positions (such as `CONC_start_idx` and `CONC_end_idx`) are left out with it, and the window reminds you that the results can't then be checked against the original text. **Select none** leaves the document ticked. The same applies to **Add to Project**.
- **Opening a CSV in Excel**: the downloaded CSV is complete and correct, but Excel splits text longer than 32,767 characters into extra rows when it opens the file, so the columns no longer line up. Leave the document column out, or open the CSV in another program.

### Hints, tabs and suggestions

- **Turning hints off shows where they come back**: a hint's **Turn off hints…** no longer turns hints off on the spot. It points at the Settings gear at the top right, then Settings points out **Guidance** and the **Show contextual hints** option, which you untick yourself, so you know where to turn hints back on. The Settings gear, then the Guidance tab, then the option pulse in turn, so you can see where to click next, and a click anywhere else (or Escape) closes the pointer if you'd rather carry on.
- **Tabs on by default**: each analysis tool now shows its tabs, so you can keep several analyses side by side; click **+** for another. A hint at **+** offers **Turn off tabs…**, which shows the way to **Settings → General → Enable multi-tab** step by step, and the **+** button's tooltip names the setting too. If you have already chosen a setting, it is kept.
- **Suggestions**: when a result or run looks off, a short suggestion with a lightbulb appears beside it, and the settings that may help pulse while it shows: a Concordance Preview that found nothing in the documents it checked, a Topic Modelling result with one huge topic or only a few topics, a Topic Modelling run still reading the text after five minutes, or a very large input before a run. Suggestions never stop you and need no closing; they fade as you carry on (typing doesn't count), or click **Dismiss** to close one now, and they come back when it happens again. If the settings a suggestion points at are scrolled out of view, they scroll back into view. Buttons that lose work, such as Clear and Stop, are named but never marked. Clicking a disabled **Run** outlines what it is waiting for, such as the tokeniser in Frequency. Turn them off under **Settings → Guidance → Show suggestions**.
- **Hints no longer get in the way**: a hint no longer dims or blocks the page. It outlines what it points at, and pulses when it points at a button to click; clicking that button does its job and closes the hint. The next hint waits until you have done something.
- **Clearer Topic Modelling notes**: the first-run time is now given for a fast recent computer, with a reminder that older or slower computers often take several times longer. When a suggestion gives the advice, the notes keep to the facts.
- **Help tooltips no longer get in the way**: a help tooltip closes as soon as the pointer leaves its icon, and the Switch Project tooltip no longer covers the Settings gear.

### Tables

- **Move columns**: in Concordance, Quotation and Annotation results, drag the grip at the left of a column header to move the column, for example a metadata column before the left context or between L1 and R1. Clicking the rest of the header still sorts. The tab remembers which columns you show and their order, and Add to Project and downloads keep that order.
- **The analysed text in Show metadata**: Concordance offers the analysed text column in **Show metadata** for Run results too, unticked at first.
- **Find columns by name**: when **Show metadata** lists many columns, a box at the top finds them by name.
- **Narrower result columns**: the grey labels under Concordance and Quotation column names are now a few words, such as *L1 frequency*; hover over a label for the full explanation.

### Export

- **Double-click adds a Data Block**: in Export, double-clicking a Data Block in the Project graph or the sidebar adds it straight away, without a second click.

### Data Editor

- **Map values**: a new **Add column** tool that makes a column from a value you type for each value of a column, for example to group parties into sides or correct spelling variants, with no regular expressions. Values are listed with their row counts, most common first or A to Z ignoring case; values you've typed are offered again so several values can share a group, and **Fill the rest** keeps the original value wherever you haven't typed one.
- **Delete columns shows examples**: each column in the Delete columns window is followed by its first value, so columns with unclear names, such as those in a survey export, are easy to recognise. A column with no values says *(empty)*.

### Help

- **Ungrouped text**: the Topic Modelling help now explains why much of a corpus can be Ungrouped, what a document's main topic means, and why a theme every document shares does not become a topic.
- **An informal benchmark**: an appendix compares Max tokens 128 and 256 on one corpus. It is one ad hoc comparison for reference, not guidance.

### Topic Modelling

- **Name your topics**: give a topic its own name, such as *Sleep* instead of *Topic 12*, with the pencil on its card in the topic list or beside the examples title, or by double-clicking that title. The name shows in the topic list, the examples title and the bubble's tooltip, and named bubbles have a bold, underlined label. Names stay with their topics when you move the **Topics** slider: a merged topic shows which named topics it includes, and moving back brings the names back. **Add to Project** writes the names into a new `TOPIC_top1_name` or `TOPIC_topic_name` column, and the interactive HTML download shows them too.
- **Latest selection on top**: the topic you select last now goes to the top of the **Selected** group, instead of being sorted by size.
- **Ungrouped instead of No topic**: passages the analysis could not place in any topic are now called **Ungrouped**, with a grey bubble in the corner of the map and a grey entry in the topic list, so documents with no topic are no longer left out without notice. You can add the Ungrouped documents to the Project like a topic. A line under the results title gives the number of documents, segments and topics, and how many documents are in a topic or Ungrouped. When many documents are Ungrouped, a suggestion tells you which settings to change.
- **Fewer giant topics**: when one topic covers most documents, **Auto** max topic size now splits it even if part of it becomes Ungrouped, instead of keeping the giant topic. Suggestions explain what a lower or higher **Max topic size** does, with a **Learn more** link to the help.
- **Colour by follows category order**: after you make a column an ordered category, the **Colour by** legend uses that order straight away, instead of keeping the order it had before.
- **Colour by explains itself**: when no column has 2 to 8 values, or the result comes from two Data Blocks, **Colour by** no longer disappears. It stays on **Data Block colour**, greyed out, and hovering over it tells you why.

### Quotation

- **Quotation Runs are several times faster**: Run now uses several processor cores at once (half of those available, up to 8) and checks each distinct text once. On a 26,000-document corpus and an 18-core Mac it takes about 6 to 7 minutes instead of 27; a 2-core BinderHub session runs as before.
- **See quotations as they are found**: while Run works, **Quotation Results so far** shows the documents checked so far, in order, and updates every few seconds. **Add to Project** and downloads wait until the Run finishes or is stopped.
- **Stop keeps what was found**: Stop finishes the few documents being checked at that moment (a few seconds) and shows everything found as the result, marked *Stopped early*, so you can add it to the Project or download it. Choose Stop again to end the Run straight away. If a Run is ended that way, fails or Wordflow restarts, the quotations found are kept in a Data Block named after the Data Block and text column, *… quotations in progress*; each text column keeps its own.
- **Resume**: while quotations are kept for the selected Data Block, text column and engine, **Run** reads **Resume** and continues from where the last Run stopped, without choosing Clear first. **Remove** on the note starts over.

### Annotation

- **No lost labels**: labels that come back from the AI provider are kept as the run goes, in a temporary Data Block named *… annotation in progress*. If a run stops early (Stop, a closed tab, a restart or power cut), the Annotation tab offers to write them into your column, so you only pay for the rest. A run that finishes removes the temporary Data Block.
- **Repeated texts sent once**: rows with the same text, such as retweets or short replies, share one answer, so the provider is asked only once for them.
- **Preview pages aren't sent twice**: the labels a Preview has received are kept with the tab and saved with the Project, so going back to a page, reloading or reopening the tab no longer asks (and pays) the provider again. A new Preview or **Clear** removes them.
- **When to use Thinking**: a help icon beside **Thinking** and a new help section explain that off (the default) is faster and cheaper, and that on can make labels more precise for complicated codes at a higher cost and slower speed.
- **Run sends only rows without a label by default**: **Which rows to annotate** now starts at **Only rows without an annotation**, so labels you already have are not sent (and paid for) again. Choose **Annotate all rows again** in **Advanced settings** when you want to replace them.
- **Requests at once**: a new setting in **Advanced settings** for how many requests Run sends at the same time: 2 for a Custom provider such as a server on your own computer, 10 for the others. Set it to your local server's own limit, so requests don't wait in its queue until they time out.
- **Thinking off now works for Custom providers**: models that think by default, such as Qwen on oMLX or vLLM, now follow the **Thinking** switch. With it off they answer with the labels straight away, instead of running out of room while thinking.
- **A slow request no longer fails the whole run**: a request that times out is tried again. If it still fails, only its rows are marked as failed and the run goes on; the run stops only when the provider stops answering.
- **Finish a stopped run without re-sending everything**: after you write the saved labels into your column, the Annotation tab offers **Annotate only the empty rows**, so the next **Run** sends only the rows still without a label. The tab keeps that choice; change it back under **Which rows to annotate** in **Advanced settings**.
- **No Clear needed after a stop or failure**: **Preview** and **Run** are available again straight away, because a new Annotation Preview or Run replaces the tab's earlier results.
- **Removing the temporary Data Block no longer shows an error**: **Remove** used to delete it but show a red error message.
- **Live progress for AI annotation**: while **Run** works, **Tasks** shows how many rows are classified, about how long is left, any failed batches, and that the run is waiting for the AI provider, so a slow provider no longer looks like a stopped run.

### Project graph

- **Data Blocks stay in place**: Data Blocks can no longer be dragged in the Project graph, so they cannot be pulled away from the rest by accident. Dragging anywhere on the graph moves the view.

### Opening Projects in older versions

- Projects with a *quotations in progress* Data Block, or a Quotation result that Stop kept, need 0.7.12 or later.
- Projects with Topic Modelling results made in 0.7.12 need 0.7.12 or later: an older Wordflow can't show those results, or topics you have named. Other analyses are not affected.

## What came in 0.7.11

Wordflow 0.7.11 lets you set the order of a category column's values and use it everywhere, including as a Trends axis; converts dates, numbers and text more reliably, checking the whole column first; adds several sheets of a spreadsheet at once; adds an Elapsed time type for transcript timestamps; shows a quick overview of a corpus in the Data Editor; makes Topic Modelling finish on large corpora and shows example texts of each topic; it also fixes Concordance's word-before column at the start of a text, sorts empty values to the bottom of every table, makes range filters behave the same for numbers and dates, and lets you add part of a folder to a Project in one step.

### Tokenisers

- **Plain words for any language**: the tokeniser formerly called "Plain words (English)" is now **Plain words**, marked *Any language with spaces*: it splits text at spaces and punctuation, so it is a baseline for French, Indonesian and any other language that separates words with spaces, and Wordflow now picks it automatically for them. Chinese, Japanese and Korean keep their own tokenisers.

### Concordance

- **L1 at the start of a text**: when a match is the first word of a text, L1 (the word just before it) is now empty, as R1 already was at the end of a text. Before, L1 showed the matched word itself, which also affected L1 counts and sorting. Text mode only; Tokens mode was right.
- **L1 and R1 colouring in Tokens mode** marks the whole word, not the same letters inside another word, for example the final *A* rather than the *a* in *cat*.
- **Ignore punctuation from a word click too**: opening Concordance by clicking a word in Frequency now has **Ignore punctuation** on, as a new Concordance tab does, so the context columns hold words and sorting is not split by punctuation.
- **Preview says how much it searched**: a Preview checks one page of documents. Its footer now says, for example, "after checking 20 of 26,163 documents" and that **Run** searches them all, so no matches in a Preview is not read as none in the corpus.
- **Download the results directly**: the download icon beside **Add to Project** saves the Concordance table as CSV or Excel, with the same column choices, in the order the table shows. It works the same in Quotation, and the Annotation tables and the Data Editor have a download icon too, so there is no need to add a table to the Project and export it.

### Category columns

- **Set the order of a category**: choosing **Category** for a column opens a window listing its values. Start from **A to Z** (numbers inside values count as numbers, so *Q9* comes before *Q10*) or, for numbers and dates, **Smallest first**; or choose **Z to A**, **Largest first**, **Most rows first** or **Fewest rows first**, or drag the values into your own order (the keyboard works too). Empty values always come last. A column with many different values, or the document column, asks before Wordflow reads and lists them all, so a mistaken click can be cancelled. The window lists up to 300 values; any others follow in the chosen order. Choose **Category** again to change the order.
- **The order is used everywhere**: table sorting, Filter's value list, Group, Trends groups, and the Topic Map colour legend.
- **Trends by category**: a category column can be the Trends axis, with one bar per value in its order and empty values as the last bar.
- **Stack** combines category columns whose orders differ, and says which order the result uses.
- **Editing a category, number or date column** with Find & replace or Clean text into the same column makes it text; Wordflow now says so, and **Undo** restores it.
- **Parquet files** that mark a category as ordered: Wordflow can't read that order and now says so, so you can set it.

### Converting column types

- **One conversion window**: changing a column from text to a date, a date and time or a number, from numbers to a date, or from a date to text, opens a window that shows what the values become and checks the whole column first, for example *2,380 of 2,400 values convert; 20 would become empty*, with the first values that don't convert.
- **More date formats**: Wordflow lists the formats that fit the column, including dates with times and time zones, month names, Twitter dates and email dates, and dates inside longer text such as the file name *2021_01_17_SmithInterview*. Dates such as *03/01/2020* are read day first; **Read month first** switches with one click.
- **No format codes needed**: each part of a value (*30*, *01*, *2020*) has a menu saying what it is, such as Day, Month or Year, or **Ignore** for text around the date. The code is still there for anyone who prefers to type it.
- **Two-digit years**: for dates such as *30/01/20*, you choose the century (1900s, 2000s, or a split year); Wordflow never guesses.
- **Numbers to dates**: Unix time (seconds, milliseconds, microseconds or nanoseconds) and Excel day numbers can become dates.
- **Text to numbers**: choose the decimal mark and thousands separator, and ignore currency signs and %, so *$1,234.50* becomes 1234.5.
- **Dates to text**: choose how the dates are written, such as *30 January 2020*, or build your own.
- **Whole numbers round to the nearest**: converting decimals to a whole number now rounds (2.5 becomes 3) instead of cutting off the decimals, and text such as *2.5* converts instead of becoming empty.

### Elapsed time for transcripts

- **A new type, Elapsed time**, for time into a recording, such as the start of each line of a transcript. It shows as *7:58.5*, or *1:23:20.25* from an hour on.
- **Spreadsheets**: a column of times without a date (Excel cells formatted like *mm:ss.0*, which used to load as dates in December 1899) now loads as elapsed time, and Wordflow says so.
- **Converting**: text such as *7:58*, *07:58.5*, *1:23:20* or subtitle-style *00:07:58,542* becomes elapsed time (a time with two parts is minutes and seconds unless you choose hours and minutes); so do numbers of milliseconds, seconds, minutes, hours or days, and the time of day of a date and time. Elapsed time becomes text in several styles, or a number of seconds, minutes or hours.
- **Using it**: sort by it, filter it by typing times like *7:58*, group it into blocks of minutes, total or average it per group (for example each speaker's speaking time), and plot it in **Trends** per second, minute, hour or a custom step. CSV exports write it as text, and Excel exports as Excel times.

### Topic Modelling

- **Large corpora finish**: a corpus of 26,000 news articles used to run for hours without finishing; it now takes about 12 minutes on a recent Mac, and a second run on the same text under a minute.
- **Faster on every core**: Topic Modelling now runs its embedding model on all processor cores on Mac and Windows, as it already did on Linux (Core ML on Mac was about 5 times slower for this model), and clustering now uses every core too.
- **Small computers too**: on a computer or virtual machine with few processors (for example 2), Topic Modelling now reads the text on all of them instead of one; in containers such as Binder it keeps to the processors it is allowed.
- **Automatic segments pack short paragraphs**: neighbouring paragraphs now share one segment while together they fit **Max tokens**, so a news article of many one-line paragraphs gives a few full segments instead of dozens of tiny ones (about 5 times fewer segments on that corpus). A paragraph is never cut to fill a segment; a paragraph too long for one segment is split into its sentences, packed the same way. Choose **Paragraph** to keep one paragraph per segment; a paragraph too long for one segment is now cut at the sentence boundary nearest its middle (and again if needed), instead of into one segment per sentence.
- **Max topic size Auto judges by documents and explains itself**: Auto now steps in when one topic is the main topic of more than half of the documents (before, more than half of the segments, which depends on the segmentation mode). The line under the settings says what it decided, for example that one topic was the main topic of 83% of documents and was split, or that splitting it would have left most of its text without a topic. After a run with Auto, the Max topic size field shows in grey the size Auto worked with, so you know which way to change it; Tab fills it in.
- **Topic sampling**: for very large corpora, a new checkbox finds the topics from a sample of segments picked with the **Seed**, then gives every other segment the topic of the sampled segment most similar to it, so every document still gets topics. It is off by default, and the note suggests it when a corpus has very many segments. **Segments to sample** shows a suggested size in grey (Tab fills it in to change it), and the note explains the trade-off: clustering time grows with the square of the sample, while a smaller sample can miss small topics.
- **Topics on the right rows**: with a Data Block made by **Join**, **Add to Project** could give a row the topics of another document, so a one-line text showed several topics. Join now keeps one row order, and Wordflow checks that the documents still match the run. To fix a Data Block made this way, choose **Add to Project** again from the same Topic Modelling result; there is no need to run Topic Modelling again.
- **Progress you can follow**: a long run now says which step it is on. In **Tasks** you see how far that step has got (for example "41,181 of 281,242 segments, about 5 min left") and how many processors it is using, so a slow computer no longer looks stuck at 10%. The Topic Modelling page shows one calm line with a link to the live progress in Tasks. Quotation and tokenising a large corpus report the same way.
- **Example texts of each topic**: click the eye at the right of a topic in the list, or right-click its bubble, to read the topic's texts beside the list. **Most typical** shows the segments closest to the centre of the topic first, **Random** a fixed random selection, and **One per document** (on by default) one segment per document. A badge such as **Top 10%** says how typical a segment is within its topic, and **Open document** shows the whole document, with the segment in bold and the topic's other segments highlighted. With **Colour by** on, the examples can be limited to one of its values. Runs from earlier versions list examples without ranking them; run again to rank them.
- **A simpler topic list**: the two topic lists are now one, with selected topics in their own group at the top, so the examples have room beside it. **Find topics** moves to the **Result settings** row, and the stop words switch is followed by a list that reads **Use stop words** until you choose one.
- **See which words matched**: while you search topics, the matching words are bold and orange in the topic list and in the word cloud shown when you hover a bubble, so a search such as `famil*` shows `family` or `familiarisation` straight away. Word order and size stay the same, and hovering a topic's word line in a list shows all of its words.

### Running analyses

- **Clear the tool caches**: **Settings → Project → Tool caches** shows how much space the Topic Modelling and Tokeniser caches use, with a **Clear** button for each. Clearing changes nothing in your Projects; the next run on the same text is slower.
- **Large caches no longer break analyses**: once a cache passed 1 GB, every later Topic Modelling or tokeniser run failed with "Something went wrong". Caches can now grow past that.
- **Quick tools never wait behind long ones**: on a shared server, Concordance, Token Frequency, Trends and the other quick tools now have their own places to run, so they start straight away even while other people's Topic Modelling or Quotation runs fill theirs.

### Tables and charts

- **Deleting a Data Block** now also closes the analysis tabs that used it, with their results, instead of leaving them without inputs and unable to take a new Data Block. Data Blocks made from it stay.
- **Help during a run**: the **?** help icons now open the help while an analysis is running; before, they were greyed out until it finished.
- **Shorter tooltips**: tooltips are now one or two short lines that wrap, instead of long explanations that could run past the edge of the window; the ? icons still open the full help.
- **Tab strips** have a slimmer scroll bar that looks the same in every browser; drag it or click it to scroll.

- **Empty values sort last**: in every table, missing values, blank text and N/A numbers now stay at the bottom whichever way you sort. Before, they came first in both directions, and N/A numbers and blank text could land anywhere.
- **Trends with too many groups**: grouping by a column with very many different values, such as the text of each line, used to freeze the page, and the saved result froze it again whenever the Project opened. Trends now draws at most 1,000 groups: such a column is flagged and Run waits for another choice, and a saved result with more groups opens to a message with **Clear** instead of freezing.
- **Trends groups**: a group column left over from the previous Data Block no longer makes the run fail.
- **Trends time axis**: the axis list offers only date, date-and-time and number columns. Times of day and durations were listed but could not be used.
- **Topic Modelling chart**: the bubbles highlighted while searching now match the topic list also when a lasso is active (before, search matches outside the lasso stayed lit). In the macOS desktop app the chart could go blank with **Fit** doing nothing until the page was zoomed; it now always shows the bubbles and fits them.
- **Topic Modelling hover cards**: while a topic search fades some bubbles, every highlighted bubble now opens its word card. Before, a faded bubble on top, or the edge of a neighbouring bubble, could catch the pointer instead. The same applies to the interactive HTML download.
- **Show metadata**: long column names, such as survey questions, now wrap in their own row instead of overlapping the names below, and the list widens to fit them. The same applies to Compare to in Annotation.
- **Trends says what it counts**: the vertical axis is titled **Rows** (or **% of rows** with **Normalise to 100%**), with whole-number steps for counts: documents for a corpus, or matches for a Data Block made by Concordance. The Trends tooltips now say this in plain words.
- **Word cloud clicks**: clicking a small word that sits inside a larger word now picks the small word, for Concordance and for adding a stop word. Before, the larger word could take the click.
- **Project graph Fit view**: **Fit view** never zooms out so far that the Data Block names cannot be read. A large Project shows its first Data Blocks and you scroll for the rest, and when zoomed out the Data Blocks sit close together instead of far apart.
- **Tooltips use current names**: tooltips and hints that still used old names and terms (such as "sequential analysis", "Apply action" or "User Files") now use the current ones.

### Data Builder

- **Filter between on numbers**: choosing **between** on a number column fills **From** and **To** with the column's smallest and largest values, so you only change the end you need.
- **Date ranges include the last day**: all range filters include both ends. On a column with dates and times, a range that ends on a plain date, such as *2020-12-31*, now includes the whole of that day; an end with a time stops at that time.

### Data Editor

- **Overview of a corpus**: **Overview** (beside **Undo**) shows the Data Block's rows and columns and, for a text column, the number of documents, empty and duplicate documents, the total number of words, and the shortest, median, mean and longest document. Words are counted between spaces, without a tokeniser; text with few spaces, such as Chinese or Japanese, is counted in characters. It is worked out when you open it, in a moment even for large corpora.

### Data Loader

- **Every sheet of a spreadsheet**: adding a spreadsheet with several sheets lists its sheets; tick the ones you want and each becomes its own Data Block. Spreadsheets inside a folder (including its subfolders), a selection or a ZIP list their sheets the same way, and clicking a sheet previews it. Before, only the first sheet of a spreadsheet in a folder or ZIP could be added.
- **ZIPs inside a ZIP or folder** are still not opened; the Add window now names them, so you can add each one on its own.

- **Add selected**: with files and folders ticked in the file list, **Add** in the selection bar adds them to the open Project, as when adding a folder: the text files as one Data Block (one row per file), or the table files as one Data Block each. To leave a few files out of a folder, tick **Select all in** the folder, untick them, then choose **Add**.
- **Download any Project**: **Download** on a Project that is not open used to fail with "Project is not open"; it now works. If the Project is open in another Wordflow window or app (for example the desktop app and a local server sharing a data folder), Download and Delete both say so and leave it untouched, as Open already did.
- **Import history**: an import that could not be finished after a restart is now listed on its own, with a way to remove it, instead of making the whole import history unreadable.
- **LDaCA collections bring in their text**: importing a collection you have access to now reads the text of each item, as the collection marks it. A transcript kept as a table, as in Sydney Speaks, comes in with one row per utterance, together with each item's details in columns starting with item_. Before, such a collection gave only one row describing it.
